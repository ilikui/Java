# 集合框架与泛型

## 常用集合如何选择

| 接口 / 类型 | 典型用途 | 需要关注 |
|---|---|---|
| `List` / `ArrayList` | 有序序列、按下标访问 | 中间插入/删除的移动成本 |
| `Set` / `HashSet` | 去重 | `equals` 与 `hashCode` 契约 |
| `Map` / `HashMap` | 键值映射 | 键唯一、哈希分布、并发安全 |
| `Queue` / `ArrayDeque` | 队列或栈式操作 | 入队/出队语义 |
| `TreeMap` / `TreeSet` | 有序键或元素 | 比较器与排序规则 |

复杂度取决于具体实现、数据分布与操作；不要把平均复杂度当作所有情况下的保证。

## 示例：统计词频

```java
import java.util.HashMap;
import java.util.Map;

public class WordCount {
    public static Map<String, Integer> count(String[] words) {
        Map<String, Integer> counts = new HashMap<>();
        for (String word : words) {
            if (word == null || word.isBlank()) {
                continue;
            }
            counts.merge(word, 1, Integer::sum);
        }
        return counts;
    }
}
```

`Map.merge` 可以表达“第一次出现设为 1，否则累加”的逻辑。实际项目中还要明确大小写、标点和 Unicode 规范化规则。

## equals 与 hashCode

若两个对象通过 `equals` 判断相等，它们必须具有相同的 `hashCode`。反过来，哈希值相同并不代表对象相等。对象放入 HashSet 或作为 HashMap 的键后，参与相等性判断的字段不应被随意修改。

## 泛型

```java
static <T> T firstOrNull(java.util.List<T> values) {
    return values == null || values.isEmpty() ? null : values.get(0);
}
```

泛型在编译期提供类型检查与更明确的 API。Java 泛型通常通过类型擦除实现，因此不能直接写 `new T()`，也不能创建 `new T[10]`。

## 常见误区

- 需要线程安全时直接假定 HashMap 可以并发写入。
- 重写 equals 却没有同步重写 hashCode。
- 把可变对象作为哈希键后又修改关键字段。
- 使用原始类型（raw type）失去泛型检查。
- 忽略 null 元素和空集合的处理策略。
