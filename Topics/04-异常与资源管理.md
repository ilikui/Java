# 异常处理与资源管理

## 异常处理原则

异常用于表达当前调用无法正常完成的情况。捕获异常的目的应是恢复、转换为更合适的业务异常，或补充上下文后继续抛出；不要无声吞掉异常。

- **受检异常**：编译器要求调用方捕获或声明。
- **运行时异常**：通常继承 RuntimeException，常用于参数错误或程序状态问题。
- **Error**：通常表示应用不应尝试常规恢复的严重问题。

## try-with-resources

```java
import java.io.BufferedReader;
import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

public class FileReaderExample {
    static String firstLine(Path path) throws IOException {
        try (BufferedReader reader = Files.newBufferedReader(path)) {
            return reader.readLine();
        }
    }
}
```

实现 `AutoCloseable` 的资源可在 try 代码块结束时自动关闭，即使中途发生异常也会尝试释放资源。

## 处理策略

1. 在边界处校验输入。
2. 只捕获能够合理处理的异常类型。
3. 保留原始异常作为 cause，避免丢失诊断信息。
4. 不使用空 catch 块。
5. 不用异常代替普通的高频分支判断。
6. 资源使用 try-with-resources，避免手动关闭遗漏。

## 自定义异常

业务异常应携带有用上下文，但不要把密码、访问令牌或完整敏感数据写入日志。对外 API 应将内部异常映射为稳定、适当的错误响应，而不是直接返回堆栈。

## 练习

- 读取不存在的文件时，设计调用方能理解的错误处理。

- 编写一个资源关闭测试，确认异常路径下资源也会关闭。
